# Contributing to @ridewolf/city-flythrough

General Ridewolf contribution rules (code of conduct, PR conventions, commit style) live
in the [organization-wide guide](https://github.com/Ridewolf/.github/blob/main/CONTRIBUTING.md) —
this file covers what's specific to this repository.

## Development setup

Requires [Bun](https://bun.sh) ≥ 1.1.

```bash
git clone https://github.com/Ridewolf/city-flythrough.git
cd city-flythrough
bun install

bun test              # 22 tests, headless
bun run lint          # biome check
bun run typecheck     # tsc --noEmit (strict)
bun run build         # dist/ — ESM + .d.ts
bun run docs:switcher # re-render the README language switcher
```

`bun install` points `core.hooksPath` at [.githooks](.githooks), where a pre-commit hook
runs the same switcher check as CI whenever a commit touches a README or the switcher
script itself — editing `LOCALES` drifts all 16 files without staging a single README.
It reads your index rather than your working tree — so its verdict is about the commit,
not about whatever you have on disk — and it never writes: if it fails, run
`bun run docs:switcher` and stage the result. It steps aside with a message rather than
blocking you when `bun` is off PATH (GUI clients, IDEs), and CI still catches the drift.

If your checkout already has hooks — a `core.hooksPath` set by husky or lefthook, or
files in `.git/hooks` from husky v4, `pre-commit`, or an IDE — the installer leaves them
alone and says so, because `core.hooksPath` would replace the lot. Call
`.githooks/pre-commit` from your own hook, or run `bun run docs:switcher:check` yourself.

## Editing the README

Only the root [README.md](README.md) is written by hand — everything under `docs/i18n/`
is generated by `docs-i18n translate` and carries a do-not-edit header.

The language switcher at the top is generated too, by
[scripts/docs-switcher.ts](scripts/docs-switcher.ts), which owns the block between the
`<!-- docs-i18n:switcher -->` markers in all 16 files. It has to, for a reason that is
easy to trip over twice: the switcher sits
inside a `<p align="center">` block, markdown is not parsed inside an HTML block, and so
`[Русский](…)` there renders as literal brackets instead of a link. The links are real
`<a href>` tags, and the translation generator does not know that — it happily writes the
markdown form back. The pre-commit hook and the CI `docs:switcher:check` step are what
keep that from shipping.

Adding a language means adding its code and native label to `LOCALES` in that script;
it fails loudly if `docs/i18n/` and that list ever disagree.

## What contributions help most

- **New block types and palettes** — waterfronts, rail lines, stadiums; a dawn or
  neon theme.
- **Vehicle variety** — buses with stops, emergency vehicles that others yield to,
  pedestrians at crossings.
- **More traffic realism** — turn signals, yellow-light dilemma zones, unequal light
  phases on avenues.

## Conventions

- **The world stays a pure function of coordinates.** Nothing about a road, block, or
  junction may be stored — that's what makes the endless camera free.
- **All randomness flows through the injected RNG.** A seeded run must be reproducible;
  the soak test depends on it.
- Canvas calls live only in `render.ts`; the simulation must stay runnable headlessly.
- New behaviours need an invariant test, not just a screenshot.
